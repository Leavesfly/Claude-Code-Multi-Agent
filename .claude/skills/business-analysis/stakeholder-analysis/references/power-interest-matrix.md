# 权力/利益矩阵的变种

## 经典权力/利益网格（Mendelow）

标准的 2x2 矩阵，以 Power 为一轴、Interest 为另一轴：

```text
           HIGH INTEREST
                │
    Keep       │    Manage
    Satisfied  │    Closely
               │
HIGH ─────────────────────── HIGH
POWER          │             POWER
               │
    Monitor    │    Keep
    (Minimal)  │    Informed
               │
           LOW INTEREST
```

### 各象限的参与策略

#### Manage Closely（高权力、高利益）

**特征：**

- 关键决策者
- 对结果投入很深
- 能显著影响成败

**策略：**

- 让其参与重大决策
- 频繁的 1:1 沟通
- 主动回应其关切
- 把他们发展成项目的旗帜人物
- 定期状态更新

**忽视他们的风险：**

- 项目被阻塞或取消
- 因临时介入导致范围蔓延
- 丧失关键支持

#### Keep Satisfied（高权力、低利益）

**特征：**

- 身居高位、但有其他优先事项
- 一旦出问题可以介入
- 通常拥有否决权

**策略：**

- 提供摘要式更新
- 适时上报问题
- 不要用细节淹没他们
- 做好应对临时请求的准备
- 理解他们的优先级

**忽视他们的风险：**

- 被意外介入打乱节奏
- 支持被撤回
- 资源被重新分配

#### Keep Informed（低权力、高利益）

**特征：**

- 通常是终端用户或受影响方
- 非常在意结果
- 正式权力有限

**策略：**

- 定期沟通
- 收集意见与反馈
- 建立支持者联盟
- 以尊重的方式回应关切
- 让其参与测试/验证

**忽视他们的风险：**

- 实施阶段出现抵制
- 负面口碑
- 采纳失败

#### Monitor（低权力、低利益）

**特征：**

- 边缘 stakeholder
- 影响/兴趣都很低
- 以后可能会产生兴趣

**策略：**

- 最少的沟通
- 仅做通用公告
- 监测其变化
- 不浪费他们的时间

**忽视他们的风险：**

- 通常风险较低
- 注意兴趣上升的迹象

## Power/Influence/Interest 立方体

针对复杂 stakeholder 场景的三维扩展：

| 维度 | 含义 | 评估方式 |
|-----------|---------|------------|
| **Power（权力）** | 正式权威 | 能否批准/否决？ |
| **Influence（影响力）** | 非正式的影响 | 他们能否说服别人？ |
| **Interest（利益）** | 关注程度 | 他们在意吗？ |

**为什么加入 Influence？**
有些 stakeholder 正式权力很低，但非正式影响力很高：

- 在团队中受尊敬的技术负责人
- 了解组织历史的资深员工
- 工会代表
- 外部行业专家

## Salience 模型（Mitchell 等）

按三种属性对 stakeholder 分类：

| 属性 | 定义 |
|-----------|------------|
| **Power（权力）** | 强加意志的能力 |
| **Legitimacy（合法性）** | 被社会认可的权威 |
| **Urgency（紧迫性）** | 诉求的时间敏感度 |

**Stakeholder 类型：**

| 类型 | Power | Legitimacy | Urgency | 策略 |
|------|-------|------------|---------|----------|
| Definitive | 是 | 是 | 是 | 最高优先级 |
| Dominant | 是 | 是 | 否 | 高度关注 |
| Dangerous | 是 | 否 | 是 | 谨慎处理 |
| Dependent | 否 | 是 | 是 | 保护其利益 |
| Discretionary | 否 | 是 | 否 | 监测 |
| Demanding | 否 | 否 | 是 | 低优先级 |
| Dormant | 是 | 否 | 否 | 观察 |

## 态度叠加

在任意矩阵上叠加对态度的评估：

| 态度 | 描述 | 行动 |
|----------|-------------|--------|
| **Champion（旗帜人物）** | 积极支持者 | 借助其支持 |
| **Supporter（支持者）** | 正面、被动 | 维持关系 |
| **Neutral（中立）** | 无强烈意见 | 提升其认知 |
| **Skeptic（怀疑者）** | 存疑但开放 | 回应其关切 |
| **Resistor（抵制者）** | 主动反对 | 理解并拉拢 |
| **Blocker（阻挠者）** | 会蓄意破坏 | 升级处理或隔离 |

**综合视图：**

```markdown
| Stakeholder | Power | Interest | Attitude | Action |
|-------------|-------|----------|----------|--------|
| CFO | High | Medium | Skeptic | Address ROI concerns |
| CTO | High | High | Champion | Leverage as sponsor |
| Users | Low | High | Supporter | Build coalition |
| IT Ops | Medium | High | Resistor | Involve early |
```

## 位置变动分析

追踪 stakeholder 位置随时间的变化：

```text
Current Position → Desired Position

            HIGH INTEREST
                 │
    [Move CFO   │    [CTO stays]
     here] ←───┼────
               │
HIGH ──────────┼─────────────── HIGH
POWER          │                POWER
               │
    [IT Ops    │    [Move Users
     starts]   │     here] ←───
               │
            LOW INTEREST
```

**移动策略：**

| 从 | 到 | 策略 |
|------|-----|----------|
| Monitor → Keep Informed | 提升认知度 | 定期更新、展示相关性 |
| Keep Satisfied → Manage Closely | 提升兴趣 | 展示战略价值 |
| Resistor → Supporter | 改变态度 | 回应关切、尽早让其参与 |
| Neutral → Champion | 建立承诺 | 展示收益、赋予 ownership |

## 评估问题

### 权力评估

| 问题 | 低 | 中 | 高 |
|----------|-----|--------|------|
| 他们能批准/否决决策吗？ | 不能 | 部分能 | 能 |
| 他们控制预算吗？ | 不 | 部分 | 完全 |
| 他们掌握所需资源吗？ | 不 | 部分 | 关键资源 |
| 他们能叫停项目吗？ | 不能 | 能拖延 | 能取消 |
| 需要他们签字吗？ | 不需要 | 有更好 | 必需 |

### 利益评估

| 问题 | 低 | 中 | 高 |
|----------|-----|--------|------|
| 结果对他们影响多大？ | 极小 | 有一定影响 | 重大影响 |
| 他们是否主动索要进展？ | 很少 | 有时 | 经常 |
| 他们会参加会议吗？ | 可选 | 有时 | 总是 |
| 他们是否表达过意见？ | 没有 | 一些 | 观点强烈 |
| 他们会使用解决方案吗？ | 不会 | 偶尔 | 每天 |

### 影响力评估

| 问题 | 低 | 中 | 高 |
|----------|-----|--------|------|
| 其他人会跟随他们吗？ | 不会 | 有时 | 总是 |
| 他们有可信度吗？ | 有限 | 受尊重 | 备受推崇 |
| 他们能影响高层意见吗？ | 不能 | 部分 | 能 |
| 他们能塑造团队文化吗？ | 不能 | 一定程度 | 显著 |
