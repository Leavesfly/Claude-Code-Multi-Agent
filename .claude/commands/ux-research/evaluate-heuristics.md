# 启发式评估

使用 Nielsen 的 10 条启发式原则进行专家可用性审查。

## 工作流程

### 步骤 1：加载所需技能

加载以下技能：

- `heuristic-evaluation` - Nielsen 的启发式原则和评估方法论

### 步骤 2：理解评估范围

收集关于 {{ interface }} 的上下文信息：

{% if scope %}范围：{{ scope }}{% endif %}

了解：

- 正在评估什么（上线产品、原型、设计稿）？
- 关键用户流程是什么？
- 是否存在已知的可用性问题？
- 目标用户是谁？

### 步骤 3：进行启发式分析

针对 Nielsen 的 10 条启发式原则，逐一评估界面：

#### 1. 系统状态的可见性

- 系统是否让用户随时了解状态？
- 是否有加载指示器、进度条？
- 操作后是否提供反馈？

#### 2. 系统与真实世界的匹配

- 语言是否对用户友好？
- 概念是否熟悉？
- 信息组织是否符合逻辑？

#### 3. 用户控制与自由

- 用户可以撤销/重做吗？
- 是否有清晰的退出路径？
- 用户可以取消操作吗？

#### 4. 一致性与标准

- 整个设计是否一致？
- 是否遵循平台约定？
- 相似的操作是否相似？

#### 5. 错误预防

- 破坏性操作是否经过确认？
- 提交前是否验证输入？
- 是否消除了容易出错的情况？

#### 6. 识别而非回忆

- 选项是否可见？
- 是否提供上下文？
- 用户是否需要记住信息？

#### 7. 使用的灵活性和效率

- 是否为专家提供快捷方式？
- 用户可以自定义吗？
- 常用操作是否优化？

#### 8. 美学与极简设计

- 信息是否优先排序？
- 是否存在视觉混乱？
- 内容是否聚焦？

#### 9. 帮助用户识别、诊断和从错误中恢复

- 错误消息是否有帮助？
- 它们是否建议解决方案？
- 错误是否清晰标示？

#### 10. 帮助和文档

- 是否在上下文中提供帮助？
- 文档是否可搜索？
- 说明是否以任务为中心？

### 步骤 4：记录发现

对于发现的每个问题：

- 界面中的位置
- 违反的启发式原则
- 严重程度（0-4）
- 描述
- 建议

### 步骤 5：生成报告

将发现汇总为优先级报告：

- 执行摘要
- 按严重程度分类的问题
- 按启发式原则分类的问题
- 建议

## 示例用法

```bash
# 完整启发式评估
/ux-research:evaluate-heuristics "项目管理仪表板"

# 聚焦评估
/ux-research:evaluate-heuristics "电子商务网站" --scope "结账流程"

# 原型评估
/ux-research:evaluate-heuristics "新入门设计"
```

## 严重程度评级指南

| 因素 | 问题 |
|--------|----------|
| **频率** | 这种情况多久发生一次？ |
| **影响** | 发生时有多严重？ |
| **持续性** | 用户可以轻松克服吗？ |

**评级决策：**

- **4（灾难性）：** 高频率 + 高影响 + 难以克服
- **3（主要）：** 常见或影响大，造成显著问题
- **2（次要）：** 偶尔不便，用户可以绕过
- **1（表面性）：** 注意到但不真正影响任务
