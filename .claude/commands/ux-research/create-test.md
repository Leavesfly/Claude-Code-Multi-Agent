# 创建可用性测试

设计完整的可用性测试计划，包括任务、主持人脚本和指标。

## 工作流程

### 步骤 1：加载所需技能

加载以下技能：

- `usability-testing` - 测试设计方法论
- `user-research-planning` - 参与者招募

### 步骤 2：理解测试上下文

收集关于 {{ feature }} 的上下文信息：

测试格式：{{ format | default: "moderated" }}

了解：

- 当前状态是什么（原型、上线产品）？
- 需要回答哪些具体问题？
- 目标用户是谁？
- 有哪些可用资源？

### 步骤 3：生成 UX 研究员 Agent

使用以下提示词生成 `ux-researcher` agent：

```text
为以下功能设计全面的可用性测试：{{ feature }}

测试格式：{{ format | default: "moderated" }}

创建以下交付物：

1. 测试目标
   - 主要可用性问题（3-5 个）
   - 功能的成功标准
   - 此测试将告知哪些决策

2. 参与者画像
   - 目标用户特征
   - 纳入/排除标准
   - 推荐的样本量及理由

3. 任务场景（5-7 个任务）
   对于每个任务：
   - 真实的场景上下文
   - 任务指令（目标，而非步骤）
   - 成功标准（二元或分级）
   - 时间基准（如适用）
   - 任务后问题

4. 主持人脚本
   - 介绍和同意书
   - 热身问题
   - 任务介绍模板
   - 出声思考提示
   - 测试后问题
   - 总结和汇报

5. 指标框架
   - 任务成功率
   - 任务时间基准
   - 错误跟踪
   - 满意度度量（SUS、SEQ）
   - 定性观察类别

6. 材料清单
   - 测试前需要准备的内容
   - 录音设置要求
   - 笔记模板

7. 分析计划
   - 如何分析发现
   - 问题严重程度评级方法
   - 报告格式

使用 usability-testing 技能获取方法论指导。
输出完整、可直接使用的测试计划。
```

### 步骤 4：生成测试材料

提供完整、可复制粘贴的材料：

- 完整主持人脚本
- 任务卡片/场景
- 笔记模板
- 测试后问卷（SUS）

## 示例用法

```bash
# 创建主持式可用性测试
/ux-research:create-test "结账流程优化"

# 创建非主持式测试
/ux-research:create-test "入门体验" --format unmoderated

# 创建游击测试
/ux-research:create-test "导航重新设计" --format guerrilla
```
